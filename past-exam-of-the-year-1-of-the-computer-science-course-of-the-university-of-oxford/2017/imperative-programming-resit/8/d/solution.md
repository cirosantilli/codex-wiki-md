The classifications and typical uses are

| Pattern | Category | When to use it |
| --- | --- | --- |
| [Command pattern](../../../../../command-pattern.md) | [Behavioral design pattern](../../../../../behavioral-pattern.md) | Represent a request as an object, separating its invocation from the receiver. Commands can be queued or logged; undo additionally needs enough information to reverse the particular request. |
| [Strategy pattern](../../../../../strategy-pattern.md) | [Behavioral design pattern](../../../../../behavioral-pattern.md) | Select among interchangeable algorithms through a common interface, such as different routing or scoring policies. |
| [Adapter pattern](../../../../../adapter-pattern.md) | [Structural design pattern](../../../../../structural-pattern.md) | Wrap an existing component so clients can use it through a different required interface without changing that component. |
| [State pattern](../../../../../state-pattern.md) | [Behavioral design pattern](../../../../../behavioral-pattern.md) | Delegate behavior to an object representing the current state, with transitions selecting another state object instead of scattering conditionals across operations. |
| [Visitor pattern](../../../../../visitor-pattern.md) | [Behavioral design pattern](../../../../../behavioral-pattern.md) | Add operations across a relatively stable element-class hierarchy, commonly through [double dispatch](../../../../../double-dispatch.md). Adding a new element type then usually requires updating the visitors. |
