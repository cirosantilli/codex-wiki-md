# Algorithm

↑ **Parent:** [Computer science](computer-science-split.md)  
ⓦ [Wiki](https://en.wikipedia.org/wiki/Algorithm)

An algorithm is a finite, precise procedure for transforming an [input](input-computer-science.md) into an [output](output-computing.md).

Here "finite" refers to the description: a short [algorithm](algorithm.md) can perform arbitrarily many steps on increasingly large [inputs](input-computer-science.md). Solving a [computational problem](computational-problem.md) additionally requires termination and the specified [output](output-computing.md) on every permitted [input](input-computer-science.md). State assumptions explicitly: [binary search](binary-search.md) requires a [sorted array](sorted-array.md).

An [algorithm](algorithm.md) is an idea that can have implementations in different [programming languages](programming-language.md). Its explanation should make three things visible: the permitted [inputs](input-computer-science.md), the rule for each step, and the meaning of the returned [output](output-computing.md). [Algorithm correctness](algorithm-correctness.md) then separates finding the right answer from eventually finishing; [time complexity](time-complexity.md) asks how much work finishing requires.

A particularly useful design question is: what knowledge survives each step? In [binary search](binary-search.md), it is the location of every possible match inside the remaining candidate range. Writing that fact as a [loop invariant](loop-invariant.md) turns an intuitive shortcut into a procedure whose discarded candidates can be justified. This often helps discover the [algorithm](algorithm.md), rather than merely check it afterward.
