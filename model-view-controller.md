# Model-view-controller

↑ **Parent:** [Software architecture](software-architecture.md)  
ⓦ [Wiki](https://en.wikipedia.org/wiki/Model–view–controller)

Separate an application's domain state and rules into a model, its presentation into a view, and interpretation of user actions into a controller. The controller requests model operations; the view renders coherent model state. A playlist model, for example, owns song order independently of whether a menu, button or keyboard action requests a move. The [Observer pattern](observer-pattern.md) often carries model-change notifications to views, but [model-view-controller](model-view-controller.md) defines responsibilities rather than requiring a particular notification mechanism. This supports [separation of concerns](separation-of-concerns.md) and testing domain logic independently of a graphical interface.
