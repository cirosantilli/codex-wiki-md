# Iterator pattern

↑ **Parent:** [Software design pattern](software-design-pattern.md)

Expose sequential consumption through availability and next-element operations while hiding storage and traversal details. The abstraction supports common clients for [arrays](array-data-structure.md), linked structures or generated [sequences](sequence.md). A separate [iterator](iterator.md) can own separate cursor state; an alias of the same [iterator](iterator.md) does not create an independent traversal.
