# Separation of concerns

↑ **Parent:** [Software engineering](software-engineering.md)  
ⓦ [Wiki](https://en.wikipedia.org/wiki/Separation_of_concerns)

Assign distinct responsibilities to components with explicit interfaces, so one responsibility can change without requiring unrelated changes elsewhere. For example, a [model-view-controller](model-view-controller.md) application separates domain state, presentation and input interpretation. The [Observer pattern](observer-pattern.md) can communicate a coherent state change to several views while keeping concrete display details out of the model. The separation should follow actual responsibilities; multiplying classes without a clear boundary does not establish it.
