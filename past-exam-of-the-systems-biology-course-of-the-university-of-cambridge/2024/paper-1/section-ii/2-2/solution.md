<h1 id="section-ii/2-2/solution">Solution</h1>

↑ **Parent:** [2.2](../2-2.md)

**Software defects can make a scientific result wrong even when another researcher reproduces it exactly.** Reducing their impact requires both a traceable computational workflow and independent checks that its implementation and scientific assumptions are appropriate.

Terminology should be stated because usage varies. Here, [computational reproducibility](../../../../../computational-reproducibility.md) means obtaining consistent results from the same data and recorded computational procedure; [scientific replication](../../../../../scientific-replication.md) means testing the finding with newly collected data or an independently conducted study. [model verification](../../../../../model-verification.md) asks whether the code implements the intended equations and rules. [model validation](../../../../../model-validation.md) asks whether those equations and rules are adequate for the scientific use. A result can pass the first two computational checks and still fail biological validation. Conversely, floating-point differences between platforms need not invalidate a conclusion if they lie within a justified numerical or statistical tolerance.

A [software bug](../../../../../software-bug.md) can enter at every stage. A sample-order mismatch may associate measurements with the wrong labels while retaining plausible matrix dimensions. An indexing or sign error can reverse a treatment contrast. Unit conversion errors can alter a kinetic rate by orders of magnitude. A mistaken stopping rule can report an optimizer's initial value as its solution. A preprocessing script can leak test-set information into training and exaggerate predictive accuracy. These failures are dangerous because an apparently reasonable plot and a successful program exit are weak tests of correctness.

Data handling provides a documented biological example. Spreadsheet defaults can coerce identifiers into dates or numbers: historical gene symbols such as SEPT2 and MARCH1 are examples of this problem. A survey found such conversions in published supplementary gene lists, demonstrating that silent changes can propagate beyond the originating analysis.[Abstract; examples of gene-symbol conversion and manual verification of affected supplementary files](../../../../../gene-name-errors-are-widespread-in-the-scientific-literature-by-mark-ziemann-and-others.md) Automatic conversion may be intended spreadsheet behavior, but it becomes a defect in an analysis that requires exact textual identifiers. Specifying identifier columns as strings, preserving stable accessions, checking uniqueness and matching against an expected identifier set directly address that failure mode.

A second example distinguishes coding errors from modeling errors. The AFNI 3dClustSim program had a defect in variance rescaling after smoothing, associated with boundary effects. Its maintainers documented the repair and assessed its consequences. Their analysis also showed why the broader problem of inflated cluster-inference false positives could not be attributed to that defect alone: assumptions about spatial autocorrelation and the inferential procedure mattered as well.[Results, “The past, I: 3dClustSim, and ‘The Bug’”; Discussion, effect of the correction](../../../../../fmri-clustering-in-afni-false-positive-rates-redux-by-robert-w-cox-and-others.md) Thus correcting an implementation is necessary but does not automatically validate the statistical method it implements.

The first defense is a clear, inspectable specification. Write down units, array meanings, intended inputs and limiting behavior; divide a pipeline into small components with explicit interfaces. A [unit test](../../../../../unit-testing.md) for a decay solver can compare against $x(t)=x_0e^{-kt}$. An [integration test](../../../../../integration-testing.md) should check the connection between data import, model fitting and plotting, including sample identifiers and units. [regression tests](../../../../../regression-testing.md) preserve justified behavior after a fix, but a saved output from an unexamined older version is not an independent truth standard. Test quality matters more than the percentage of lines executed.

Exact reference answers are often unavailable, so [property-based testing](../../../../../property-based-testing.md) and [metamorphic testing](../../../../../metamorphic-testing.md) are valuable. A closed chemical conversion should conserve total material; a [probability](../../../../../probability.md) vector should be nonnegative and sum to one; consistently permuting independent sample rows should leave a deterministic fitted model unchanged. A valid metamorphic relation must match the problem: permuting a time series would generally destroy temporal information rather than preserve the expected result. Testing extreme inputs, empty groups and zero-rate cases often exposes bugs that ordinary examples miss. Code review and an independently written implementation can find shared blind spots that additional tests derived from the same erroneous formula cannot.[sections on modular development, testing, assertions and collaborative code review](../../../../../best-practices-for-scientific-computing-by-greg-wilson-and-others.md)

Numerical algorithms introduce another layer. For explicit Euler integration of $\dot x=-kx$, the update is $x_{n+1}=(1-kh)x_n$. The exact solution is positive and decays, but $kh>2$ makes the discretization unstable, and even $1<kh<2$ produces alternating negative values. This can be an unsuitable algorithm or step size rather than a typographical defect. Comparing step sizes, solver tolerances and alternative algorithms separates discretization error from a biological prediction. In a sensitive dynamical system, convergence of statistical summaries may be more meaningful than exact agreement of a long trajectory.

Traceability makes failures discoverable and corrections usable. [version control](../../../../../version-control.md) identifies the code revision that generated a result; [data provenance](../../../../../data-provenance.md) records raw inputs, reference annotations, filtering decisions and transformations. An executable workflow regenerates outputs from those inputs without undocumented manual edits. Dependency versions and a recorded environment, possibly a [software container](../../../../../software-container.md), reduce accidental differences between installations. A [random seed](../../../../../random-seed.md) should be recorded together with the generator and, where relevant, the allocation of streams to parallel workers. One seed is not an uncertainty estimate, and parallel scheduling or library changes can defeat bitwise repetition even when it is reused.

[continuous integration](../../../../../continuous-integration.md) can run focused tests whenever the analysis changes, while release notes and archived versions let readers distinguish corrected results from earlier ones. The environment archive preserves the ability to reproduce an old computation; the maintained version should also contain the scientific correction. Publishing only a container that reliably reproduces a wrong result is inadequate. When a defect is found, quantify which conclusions change, rerun affected analyses, retain a minimal reproducing example and communicate the correction through the appropriate scientific record. **Reliable computational science combines reproducible execution, verified implementation, quantified numerical error and validation against evidence; none is a substitute for the others.**
