# Data structure

↑ **Parent:** [Computer science](computer-science-split.md)  
ⓦ [Wiki](https://en.wikipedia.org/wiki/Data_structure)

A [data structure](data-structure-split.md) organizes stored information together with operations for accessing and changing it. Choosing a [data structure](data-structure-split.md) means choosing which questions should be cheap to answer: an [array](array-data-structure.md) supports access by numbered position, a [hash table](hash-table.md) supports lookup by key, and a [priority queue](priority-queue.md) supports selecting an item by priority. The operations and their [time complexity](time-complexity.md) matter as much as the stored values.

Suppose three requests arrive as $(5,\mathrm{Ada}),(2,\mathrm{Bo}),(4,\mathrm{Cy})$, where the number is a priority and smaller numbers are more urgent. A [FIFO queue](fifo-queue.md) removes Ada first because she arrived first. A minimum-oriented [priority queue](priority-queue.md) removes Bo first because $2$ is the least priority. An [array](array-data-structure.md) can store the same three records in arrival order, but finding the least priority by scanning this representation takes three key inspections. A [binary heap](binary-heap.md) organizes these records so the least priority is immediately available. The information is the same; the representation changes the work needed to use it.

This is a useful design principle: preserve just enough organization for the operations the application needs. Maintaining a [sorted array](sorted-array.md) gives the whole order, but moving entries to insert a new key can be expensive. A [binary heap](binary-heap.md) keeps a weaker [heap order](heap-order.md) that supports fast repeated selection without maintaining a [sorted array](sorted-array.md). A good [data structure](data-structure-split.md) makes an [algorithm](algorithm-split.md)'s next step easy.
